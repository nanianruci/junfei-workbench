**上传前复核中补修的三个问题**

1. 商品累积超过 30 个图片任务后，较早的未知提交或已完成七图可能移出最近记录，导致再次开放首色派单。协作接口现在始终纳入会阻止重新派单的原任务。回归同时覆盖旧未知提交、旧七图和 31 个更新的修图任务。
2. 美国单站发布曾在英国协作页显示刊登阶段并提供观察动作。现在阶段、动作和回执共用原任务的站点范围，早期未记录站点字段的双站任务沿用发布模块的默认规则。
3. Codex 已记录外部执行意图、原生任务尚无回执时，轮转曾允许淘汰当前商品。现在淘汰会按账号和商品查找所有站点的原派单，给出待核对请求编号，并保留当前分配及计数。

**提交范围和已知限制**

上传时需包含新增的 `browser_space_lock.py`、`image_engine_delivery.py`、`store_rotation.py`、`workspace_backup.py`、前端组件及其测试。仅提交已跟踪文件会漏掉后端导入和前端构建所需的源码。文件清单已检查 Git 忽略规则，常见私钥与服务令牌格式筛查未命中。运行库、凭据、业务数据及第三方图片资产沿用仓库忽略规则。

本次验证使用隔离任务与模拟外部服务。真实模板资产、GPU 或付费出图、1688 登录态采集、ERP 写草稿和正式刊登仍需目标机验收。独立便携 EXE 的刊登脚本清单尚未包含源码发布器使用的 `ego-publication-workflow.mjs` 与 `atomic_write_json.mjs`，本次交付范围为源码。跨进程崩溃后的持久浏览器协调、跨模块统一任务监督和文本费用硬上限仍待实施。
